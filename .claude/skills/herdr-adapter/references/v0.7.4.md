# herdr 0.7.4 recipes

Helper used throughout (no jq on this machine):

```bash
jget() { python3 -c "import sys,json,functools; d=json.load(sys.stdin); print(functools.reduce(lambda a,k: a[int(k)] if isinstance(a,list) else a[k], sys.argv[1].split('.'), d))" "$1"; }
```

## R1 — env + version gate

```bash
test "${HERDR_ENV:-}" = 1 || echo "NOT-INSIDE-HERDR"
herdr --version          # pin: herdr 0.7.4
herdr status             # server running, compatible: yes
```

## R2 — spawn a worker pane (sibling split, background)

```bash
herdr pane layout --pane "$HERDR_PANE_ID"    # wide → split right; narrow/tall → down
out=$(herdr pane split --current --direction right --no-focus)
pid=$(printf '%s' "$out" | jget result.pane.pane_id)
herdr pane rename "$pid" "w-<slug>"
```

If the JSON shape differs, print `$out` and read the pane id from it. Record `$pid` in the task card immediately.

## R3 — launch a worker Claude in the pane

```bash
herdr pane run "$pid" "cd <project-path from the registry index> && SHEPHERD_TASK_ID=T-NNNN SHEPHERD_STATUS_FILE=<shepherd-root>/ledger/status/T-NNNN.jsonl CLAUDE_CODE_SUBAGENT_MODEL=opus claude --model fable --effort <high|max> --permission-mode auto"
herdr wait agent-status "$pid" --status idle --timeout 45000
```

- Tier standard → `--model fable --effort high`; heavy → `--model fable --effort max`.
- `CLAUDE_CODE_SUBAGENT_MODEL=opus` pins every subagent a worker spawns (SDD implementers, Explore, Plan) to Opus — it outranks per-call overrides and agent frontmatter (no implementation subagent below Sonnet, ideally Opus). Subagent *effort* has no env control; it inherits the worker's effort, which is fine (high/max is at or above the intended floor).
- If `--permission-mode auto` errors at launch (not yet verified): relaunch without the flag, note it in the card Log, and raise with the operator before dispatching more work.
- `pane run` submits text + Enter atomically. Keep every line sent through it single-line, no double quotes.

## R4 — kickoff / follow-up prompt to a worker

```bash
herdr pane run "$pid" "You are a shepherd worker. Read <shepherd-root>/ledger/tasks/T-NNNN.md and execute its Brief exactly."
```

The Brief lives in the card file — never push multi-line briefs through the pane.

## R5 — watch for completion (arm BOTH as BACKGROUND Bash tasks; either's exit wakes you)

Primary — **ground-truth watcher**: fires ~2s after the worker's Stop hook writes a terminal claim. Immune to herdr's focus/seen semantics.

```bash
timeout 900 sh -c 'until grep -q "\"claim\": \"\(done\|blocked\|failed\)\"\|\"event\": \"notification\"" "$1" 2>/dev/null; do sleep 2; done' _ <shepherd-root>/ledger/status/T-NNNN.jsonl
```

Exit 0 = terminal claim written OR a Notification-hook event (permission/idle prompt — worker stuck mid-turn); exit 124 = 15-min heartbeat with nothing new. Either way: run the monitor skill.

**Where notification events land is inconsistent** — notifications have been observed both in sibling `T-NNNN.blockN.jsonl` files and in the main `T-NNNN.jsonl`. (The `blockN`/`notifN` siblings are shepherd's own rotations of consumed files, not a hook convention.) Watch the glob so either case fires; the secondary herdr `blocked` watcher remains the reliable catcher for permission prompts:

```bash
timeout 900 sh -c 'until ls <shepherd-root>/ledger/status/T-NNNN*.jsonl >/dev/null 2>&1 && grep -qh "\"claim\": \"\(done\|blocked\|failed\)\"\|\"event\": \"notification\"" <shepherd-root>/ledger/status/T-NNNN*.jsonl 2>/dev/null; do sleep 2; done'
```

Secondary — **stall watcher**: catches approval/permission prompts that pause the worker *without* ending its turn (no Stop hook → no status line).

```bash
herdr wait agent-status "$pid" --status blocked --timeout 900000
```

Wake rules:
- Whichever exits first, run monitor's ladder. The sibling watcher fires later — **a wake for a task already closed or already being handled is a no-op; don't re-arm it.**
- **Why we don't wait on `done`** (verified live against herdr 0.7.4): completion in a *focused* tab reports `idle`, never `done`, so a `--status done` wait can only expire at its timeout — a built-in 15-minute delay whenever the operator is watching the pane. `idle` vs `done` still both mean "completed" when *reading* state (R7).
- 0.7.4 quirk, if you ever do need a `done` wait: it exists only on top-level `herdr wait agent-status` (`herdr agent wait --status` doesn't accept it).
- herdr wait timeouts exit 1 with JSON on stderr — heartbeat path, not an error.
- On any wake where completion is unconfirmed, run R7 and treat `idle`|`done` as completed, `blocked` as needs-input, `unknown` as inspect (R6).

## R6 — read a worker's recent output (does NOT mark it seen)

```bash
herdr pane read "$pid" --source recent-unwrapped --lines 120
```

Scan for approval/question UI before believing any completed state — herdr's Claude detection is screen-scraped and a novel prompt can render as `idle` instead of `blocked`. `herdr agent explain "$pid"` debugs misclassification.

## R7 — status snapshot

```bash
herdr pane get "$pid"     # agent, agent_status, agent_session (Claude session id → claude --resume)
herdr agent list          # all live agents
herdr pane list --workspace "$HERDR_WORKSPACE_ID"
```

Backfill the card's `session:` from `agent_session` when present. The worker's full transcript path arrives via the Stop hook in the status file (`transcript_path`) — read it there, not from herdr.

## R8 — notify the operator

```bash
herdr notification show "T-NNNN done" --body "<one line>" --sound done      # completion
herdr notification show "T-NNNN needs you" --body "<one line>" --sound request   # escalation
```

Operator block says `notifications: silent` → omit the `--sound` flag (toast still shows).

## R9 — retire a worker pane after its task closes (pane hygiene)

Closing the pane also ends the claude session — this is the normal close-out path. **Never send `/exit` first**: `pane run` appends to any unsubmitted draft in the input box and would submit it as a prompt.

```bash
herdr pane get "$pid"     # gather guard facts
```

Guards — ALL must pass, else leave the pane open and note which guard failed in the card Log:

1. Task card is `done|failed|abandoned` AND the card's `pane:` == `$pid` (shepherd-created, this task's).
2. `label` starts with `w-` and `agent_status` is `idle`/absent — never close a `working`/`blocked` agent.
3. `agent_session` matches the card's `session:` — a different session id means a human ran their own claude in the pane; leave it alone.
4. `focused` is false — the operator is looking at a focused pane; skip and retry on a later wake.
5. Unsubmitted input-box drafts do NOT block retirement — discard silently.

```bash
herdr pane close "$pid"             # then set registry `pane:` to none if it pointed here
```

Keep-the-pane variant (rare — immediate relaunch in the same pane): `herdr pane run "$pid" "/exit"` drops to shell — but ONLY after an R6 read confirms the input box is empty.

## Gotchas (0.7.4)

- IDs are opaque; never constructed; re-read after any mutation. A moved pane gets a NEW id.
- `agent send` writes literal text WITHOUT Enter — do not use for prompting; use `pane run`.
- Agent names clear when the agent exits/is replaced — the ledger keys on **pane ids**, names are cosmetic labels.
- No CLI event push on 0.7.4 — blocking waits (R5) are the only signal; the Stop-hook status file is the compensating ground truth.
- Never run a mutating command bare to "see its help" (`herdr workspace create` executes with defaults) — command-group help only (`herdr pane`, etc.).
