# herdr 0.8.2 recipes

Helper used throughout (no jq assumed):

```bash
jget() { python3 -c "import sys,json,functools; d=json.load(sys.stdin); print(functools.reduce(lambda a,k: a[int(k)] if isinstance(a,list) else a[k], sys.argv[1].split('.'), d))" "$1"; }
```

## R1 — env + version gate

```bash
test "${HERDR_ENV:-}" = 1 || echo "NOT-INSIDE-HERDR"
herdr --version          # pin: herdr 0.8.2
herdr status             # server running, compatible: yes
```

## R2 — spawn a worker pane (sibling split, background)

```bash
herdr pane layout --pane "$HERDR_PANE_ID"    # wide → split right; narrow/tall → down
out=$(herdr pane split --current --direction right --no-focus)
pid=$(printf '%s' "$out" | jget result.pane.pane_id)
herdr pane rename "$pid" "w-<slug>"
```

If the JSON shape differs, print `$out` and read the pane id from it. Record `$pid` in the task card immediately.

## R3 — launch a worker Claude in the pane

```bash
herdr pane run "$pid" "cd <project-path from the registry index> && SHEPHERD_TASK_ID=T-NNNN SHEPHERD_STATUS_FILE=<shepherd-root>/ledger/status/T-NNNN.jsonl CLAUDE_CODE_SUBAGENT_MODEL=opus claude --model opus --effort <high|xhigh> --permission-mode auto"
herdr agent wait "$pid" --until idle --timeout 45000
```

- Tier standard → `--model opus --effort high`; heavy → `--model opus --effort xhigh`. **Another model — `fable`, say — only on the operator's specific request, and then only at `--effort high`.** Never `fable --effort max`. Check `claude --help` for the current aliases and effort levels before departing from the default; at the time of writing `--model` takes `fable`, `opus`, `sonnet` or a full id, and `--effort` takes low, medium, high, xhigh, max.
- `CLAUDE_CODE_SUBAGENT_MODEL=opus` pins every subagent a worker spawns (SDD implementers, Explore, Plan) to Opus — it outranks per-call overrides and agent frontmatter (no implementation subagent below Sonnet, ideally Opus). Subagent *effort* has no env control; it inherits the worker's effort, which is fine (high/xhigh is at or above the intended floor).
- If `--permission-mode auto` errors at launch: relaunch without the flag, note it in the card Log, and raise with the operator before dispatching more work.
- `pane run` submits text + Enter atomically. Keep every line sent through it single-line, no double quotes.
- **`herdr agent start` changed shape in 0.8.x** and is an alternative to the `pane run` launch above: `herdr agent start <name> --kind claude --pane <id> [--timeout MS] [-- <agent-arg>...]`. It takes **no topology flags** — split the pane first (R2), and the pane must already sit at an interactive shell prompt. It returns only once the expected agent is detected and ready, which folds R3's readiness wait into the call. Shepherd keeps using `pane run` because the launch line carries `SHEPHERD_TASK_ID`/`SHEPHERD_STATUS_FILE` env, which `agent start` has no way to inject.

## R4 — kickoff / follow-up prompt to a worker

**0.8.2 changes the preferred form.** `herdr agent prompt` is atomic (submits text + Enter) *and* can confirm the prompt landed in the same call, replacing the R3-era `pane run` + separate wait:

```bash
herdr agent prompt "$pid" "You are a shepherd worker. Read <shepherd-root>/ledger/tasks/T-NNNN.md and execute its Brief exactly." --wait --until working --timeout 15000
```

Three behaviours to know, all from the binary's own help — do not assume them away:

- **A blocked agent rejects the submission** with `agent_blocked` *before any input is sent*. This is a safety win over `pane run`, which would have appended the text to whatever dialog or draft was on screen. Treat `agent_blocked` as "read the pane first" (R6), never as a transport failure.
- **`--wait` does not track turns.** If the agent is already `working`, that turn's completion may satisfy the wait. For a kickoff into an idle pane this is fine; for a follow-up into a busy worker it is not — prompt without `--wait` and let R5's watchers report.
- From a non-working start, `--wait` first needs an observed state change within 5000ms or it returns `agent_prompt_stalled`; a shorter `--timeout` returns `timeout` instead.

`herdr pane run` still exists and is still correct for shell commands (R3's launch line). Use `agent prompt` only for talking to an agent.

The Brief lives in the card file — never push multi-line briefs through the pane. Keep anything sent through either verb single-line and free of double quotes.

## R5 — watch for completion (arm BOTH as BACKGROUND Bash tasks; either's exit wakes you)

**Heartbeat timeout is a BACKSTOP, not the signal**: the watchers fire event-driven within seconds of a Stop-hook write or a permission prompt; the timeout only catches crashed workers, hook write failures, and herdr misclassification. Set `HB` per task tier: **1800 (30m) for S/M, 3600 (60m) for L/heavy** — and the herdr wait gets `HB * 1000` ms.

Primary — **ground-truth watcher**: fires ~2s after the worker's Stop hook writes a terminal claim. Immune to herdr's focus/seen semantics.

```bash
timeout $HB sh -c 'until grep -q "\"claim\": \"\(done\|blocked\|failed\)\"\|\"event\": \"notification\"" "$1" 2>/dev/null; do sleep 2; done' _ <shepherd-root>/ledger/status/T-NNNN.jsonl
```

Exit 0 = terminal claim written OR a Notification-hook event (permission/idle prompt — worker stuck mid-turn); exit 124 = heartbeat with nothing new. Either way: run the monitor skill.

**Where notification events land is inconsistent** — notifications have been observed both in sibling `T-NNNN.blockN.jsonl` files and in the main `T-NNNN.jsonl`. (The `blockN`/`notifN` siblings are shepherd's own rotations of consumed files, not a hook convention.) Watch the glob so either case fires; the secondary herdr `blocked` watcher remains the reliable catcher for permission prompts:

```bash
timeout $HB sh -c 'until ls <shepherd-root>/ledger/status/T-NNNN*.jsonl >/dev/null 2>&1 && grep -qh "\"claim\": \"\(done\|blocked\|failed\)\"\|\"event\": \"notification\"" <shepherd-root>/ledger/status/T-NNNN*.jsonl 2>/dev/null; do sleep 2; done'
```

Secondary — **stall watcher**: catches approval/permission prompts that pause the worker *without* ending its turn (no Stop hook → no status line).

```bash
herdr agent wait "$pid" --until blocked --timeout $((HB * 1000))
```

Wake rules:
- Whichever exits first, run monitor's ladder. The sibling watcher fires later — **a wake for a task already closed or already being handled is a no-op; don't re-arm it.**
- **Why we don't wait on `done`** (verified live): completion in a *focused* tab reports `idle`, never `done`, so a `--until done` wait can only expire at its timeout — a built-in delay of the full heartbeat whenever the operator is watching the pane. `idle` vs `done` still both mean "completed" when *reading* state (R7).
- 0.8.2: the top-level `herdr wait` group is GONE. `herdr agent wait <target> --until <status>` is the only form, `--until` is **repeatable**, and it accepts `done` (the 0.7.4 split between the two wait surfaces no longer exists). With no `--until` it matches `idle`, `done` or `blocked` — usually what you want. With no `--timeout` it waits **forever**: always pass one.
- herdr wait timeouts exit 1 with JSON on stderr — heartbeat path, not an error.
- **NEVER pipe a watcher command.** `herdr agent wait ... 2>&1 | head -3` reports **`head`'s** exit status, not herdr's, so a timeout arrives looking like exit 0 — indistinguishable from a genuine `blocked` hit. Verified: run unpiped, a timeout is rc 1 with `{"error":{"code":"timeout"}}` on stderr; run through `| head`, it is rc 0. Arm every watcher as a bare command and read its output file if you need the text. A watcher whose exit code is masked is worse than no watcher — it turns every heartbeat into a false escalation.
- **`agent wait --timeout` is honoured when the command is not piped.** An earlier note here claimed it returned early after ~35 minutes on a 60-minute arm. That measurement came from a run piped through `head`, and it is **withdrawn**: the unpiped re-arm ran about 67 minutes for a `--timeout 3600000` and exited 1 with `{"error":{"code":"timeout"}}` on stderr exactly as documented. Both symptoms of that first run — the early return and the exit code 0 — trace to the pipe, not to herdr. Arm watchers bare; see the rule above.
- On any wake where completion is unconfirmed, run R7 and treat `idle`|`done` as completed, `blocked` as needs-input, `unknown` as inspect (R6).

## R6 — read a worker's recent output (does NOT mark it seen)

```bash
herdr pane read "$pid" --source recent-unwrapped --lines 120
```

Scan for approval/question UI before believing any completed state — herdr's Claude detection is screen-scraped and a novel prompt can render as `idle` instead of `blocked`. `herdr agent explain "$pid"` debugs misclassification.

## R7 — status snapshot

```bash
herdr pane get "$pid"     # agent, agent_status, agent_session (Claude session id → claude --resume)
herdr agent list          # all live agents
herdr pane list --workspace "$HERDR_WORKSPACE_ID"
```

Backfill the card's `session:` from `agent_session` when present. The worker's full transcript path arrives via the Stop hook in the status file (`transcript_path`) — read it there, not from herdr.

**Own identity (multi-instance).** Your own pane is `$HERDR_PANE_ID`; your own session id is the `agent_session` herdr reports for it:

```bash
herdr pane get "$HERDR_PANE_ID"   # .result.pane.agent_session.value
```

Two traps here, both checked against the real binary, not assumed:

- `agent_session` is a **nested object**, not a string — the id is at `.value`, e.g. `.result.pane.agent_session.value`.
- Do not assume `jq` is installed; parse with `python3`.

**`herdr pane get` does NOT exit 0 for a missing pane.** A live pane: exit 0, the pane document on stdout. A missing pane: exit 1, a `{"error":{"code":"pane_not_found",...}}` document on **stderr**, stdout empty. Verified directly against 0.8.2 (behaviour unchanged from 0.7.4):

```
$ out=$(herdr pane get wP:pZZZ 2>/dev/null); echo "rc=$? stdout=[$out]"
rc=1 stdout=[]
$ herdr pane get wP:pZZZ 2>&1 >/dev/null
{"error":{"code":"pane_not_found","message":"pane wP:pZZZ not found"},"id":"cli:pane:get"}
```

Even so, never read the exit status as the signal — a herdr-unreachable failure or a malformed document can also make it non-zero, and nothing but the `pane_not_found` code itself tells that apart from "pane gone". `scripts/lib/shepherd-common.sh`'s `pane_probe <pane>` is the sanctioned reader: it takes stdout, falling back to stderr only when stdout is empty, and classifies whichever document it finds — never the exit code. It returns **three** states, not two:

| Return | Meaning |
|---|---|
| 0 | live — pane exists and runs a Claude session; prints the session id |
| 1 | gone — `pane_not_found`, or the pane carries no usable `agent_session` |
| 2 | unresolved — no document on either stream, not JSON, any other error code, or no usable pane object; anything else, including a missing `python3` (which propagates 127 and is normalised to 2 by `shepherd_live`) |

`pane_session <pane>` is `pane_probe` under another name (same three returns) for callers that just want an id. `shepherd_live <pane> <session>` composes it with a recorded session id for the same tri-state answer: 0 only when the pane runs exactly that session. **Only a 1 ever authorises reclaiming a lock or reservation** — a 2 is reported, never treated as gone (see the sweep line kinds, CLAUDE.md §8).

**Peer identity (multi-instance).** A peer's pane and session are never read from herdr directly — they come from its identity lock:

```bash
scripts/lock.sh check <owner-id>   # HELD <owner-id> <holder> <pane> <session> <task> <acquired>
```

Fields 4 and 5 of that line are the pane and session to probe. (`ledger/shepherds/<id>.json` is only the advisory copy of the same facts — its directory is gitignored and may be empty; the lock is the authority, never the registration file.)

`shepherd_live` and `pane_probe` are shell functions in `scripts/lib/shepherd-common.sh`, not a standalone command — that library's own header says "never executed directly". Source it, then call the function directly:

```bash
. scripts/lib/shepherd-common.sh; shepherd_live <pane> <session>; echo $?
```

## R8 — notify the operator

```bash
herdr notification show "T-NNNN done" --body "<one line>" --sound done      # completion
herdr notification show "T-NNNN needs you" --body "<one line>" --sound request   # escalation
```

Operator block says `notifications: silent` → omit the `--sound` flag (toast still shows).

A `disabled` result is an expected outcome, not a failure: herdr notifications are optional and may be off on this machine. Discard it silently and carry on — chat is the escalation channel that always works.

## R9 — retire a worker pane after its task closes (pane hygiene)

Closing the pane also ends the claude session — this is the normal close-out path. **Never send `/exit` first**: `pane run` appends to any unsubmitted draft in the input box and would submit it as a prompt.

```bash
herdr pane get "$pid"     # gather guard facts
```

Guards — ALL must pass, else leave the pane open and note which guard failed in the card Log:

1. Task card is `done|failed|abandoned` AND the card's `pane:` == `$pid` (shepherd-created, this task's).
2. `label` starts with `w-` and `agent_status` is `idle`/absent — never close a `working`/`blocked` agent.
3. `agent_session` matches the card's `session:` — a different session id means a human ran their own claude in the pane; leave it alone.
4. `focused` is false — the operator is looking at a focused pane; skip and retry on a later wake.
5. Unsubmitted input-box drafts do NOT block retirement — discard silently.

```bash
herdr pane close "$pid"             # then set registry `pane:` to none if it pointed here
```

Keep-the-pane variant (rare — immediate relaunch in the same pane): `herdr pane run "$pid" "/exit"` drops to shell — but ONLY after an R6 read confirms the input box is empty.

## R10 — self-recycle (context reset in place)

Shepherd resets its own context with `/clear` while keeping the same process (and any remote-control registration) alive — the user sees one continuous stream.

Meter (run on wakes): `scripts/self-recycle.sh decide` → `ok|hold|recycle|unknown`, read from the **status line in your own pane** (`ctx … NN%`, rendered by `~/.claude/statusline.py`). `scripts/self-recycle.sh ctx` prints the bare percent. Thresholds — absolute tokens OR percent, whichever fires first: **≥200k tokens or ≥60 % with no active card you own; ≥350k tokens or ≥85 % regardless** → recycle; only between tasks/wakes — never mid-verification. The legacy `meter <own-session-id>` (transcript-derived tokens, ~300k ≈ the old threshold) is the fallback when the status line is not visible.

Recycle sequence (all in ONE turn, then end the turn):

1. Commit every pending ledger/registry change (durable state is the repo).
2. **Check the input box is in normal prompt mode** — R6 read of own pane. See the bash-mode trap below; skipping this is how the whole sequence fails silently.
3. Arm the detached recovery injector (survives /clear; waits for own pane idle, then prompts). **Phrase it so it is true whether or not the clear worked** — never assert freshness:
   `scripts/self-recycle.sh inject <own-pane> 30 "Run session-start recovery per CLAUDE.md section 8 and report status to the operator."`
4. Queue the clear into own pane (executes when this turn ends): `herdr pane run <own-pane> "/clear"`
5. End the turn. Do NOT queue anything after /clear — queued messages likely do not survive it; that is what the injector is for.

**Bash-mode trap — this sequence has failed here in practice.** `pane run` submits into whatever mode the input box is currently in. If the operator last ran a command with the `!` prefix, the box is in **bash mode**, and `pane run "/clear"` executes `/clear` as a *shell command* — it fails with `/bin/bash: /clear: No such file or directory` and the context is never cleared. Two consequences, both bad: shepherd carries on believing it recycled, and the already-armed detached injector later fires into a session that is not fresh, asserting a false premise. Mitigations, in order: R6-read the pane before queuing (step 2); keep the injector message premise-free (step 3); and if the clear did not take, `pgrep -af "session-start recovery"` and kill the injector before doing anything else. When in doubt, ask the operator to type `/clear` themselves — that always works and costs one message.

Known facts: /clear keeps PID + remote-control registration (phone-side sync can glitch; registration persists); a full restart mints a NEW remote session — never restart when continuity matters; Claude Code has no programmatic clear — herdr self-injection is the mechanism; background Bash watchers do NOT survive /clear — CLAUDE.md §8 recovery re-arms them from active task cards.

## New in 0.8.2 (not yet used by shepherd — noted so nobody re-invents them)

Protocol went 16 → 20 across 0.7.4 → 0.8.2. One socket method was removed (`agent.send`); seven were added.

## Gotchas (0.8.2)

- **Re-arming after a consumed claim:** a naive re-arm of the R5 grep fires instantly on the already-handled terminal claim still sitting in the file. **Anchor on the COUNT OF TERMINAL CLAIMS, not on line count:**

  ```bash
  C=$(grep -c '"claim": "\(done\|blocked\|failed\)"' "$F")
  timeout $HB sh -c 'until [ "$(grep -c "\"claim\": \"\(done\|blocked\|failed\)\"" "$1")" -gt "$2" ]; do sleep 2; done' _ "$F" "$C"
  ```

  **Do NOT write `|| echo 0` on that `grep -c` — it has silently killed a watcher.** `grep -c` prints `0` **and exits 1** when there are no matches, so `C=$(grep -c ... || echo 0)` yields the two-line string `0\n0`. `[ "$n" -gt "$C" ]` then fails every iteration with `[: Illegal number: 0`, the loop spins until its timeout, and **the watcher never fires**. The failure is silent and looks exactly like a quiet worker — the completion was only caught because an unrelated stale watcher happened to wake shepherd. `grep -c` already prints `0` on no-match, so the bare form is correct; if you want a guard against a missing file, use a parameter default instead:

  ```bash
  C=$(grep -c '"claim": "\(done\|blocked\|failed\)"' "$F" 2>/dev/null); C=${C:-0}
  ```

  General rule for every watcher: **a wait that can only ever time out is worse than no wait**, because a heartbeat exit is indistinguishable from a healthy quiet task. Sanity-check a re-armed watcher by confirming its condition is false at arming time.

  The older `wc -l` anchor is unreliable and has misfired: `wc -l` counts newlines, so a status file whose last line has no trailing newline reads one short. The hook writes land unterminated and gain their newline later, so the anchor is set too low and the watcher fires on a line it was meant to skip. Counting claims is immune — the count only rises when a genuine new terminal claim is appended, whatever the newline state. Trade-off: this ignores `"event": "notification"` lines, so pair it with the R5 secondary stall watcher when a mid-turn permission prompt is plausible; for a worker parked on a checkpoint awaiting the operator, ignoring notifications is exactly what you want.
- **Interactive dialogs in a worker:** Claude Code onboarding/select dialogs (e.g. "Set up auto mode?") swallow `pane run` input — the trailing Enter confirms whatever is highlighted (sending `3` ENTERED the wizard instead of dismissing). Use `herdr pane send-keys <pane> Escape` to cancel dialogs; verify with an R6 read before sending any prompt.

- IDs are opaque; never constructed; re-read after any mutation. A moved pane gets a NEW id.
- **Claude Code renders a SUGGESTED prompt inside the input box, and a pane read cannot tell it from typed text.** An idle worker once showed `❯ Empty shepherds is fine, degraded says why - keep going`. That was Claude Code's own suggested next prompt, not something the operator typed. Reading it as a human draft, shepherd refused to prompt the worker (to avoid appending to a real draft), escalated, and held a finished worker idle for nearly an hour for nothing.

  **A genuinely empty box renders as a bare `❯` with nothing after it.** A suggestion renders identically to typed input in every snapshot source — `visible`, `recent`, `recent-unwrapped` and `detection` all show the same characters. There is no source that distinguishes them.

  **The rule that actually applies: shepherd is in control of the worker pane and prompts it whenever it judges it should, even with a human apparently present. Only the operator specifically saying stand down changes that.** Apparent text in a box is never a reason to hold a task. If a prompt would append to something real, lead with a separator so the combined line reads coherently — a formatting problem, not a stop condition. The cost of a wrong nudge is one line in a pane; the cost of a wrong hold is unbounded.

  Confirming the prompt landed is the cheap check either way: `agent prompt` returns the post-submission status, and a follow-up `pane read` shows a bare `❯` once the box is genuinely clear.
- **`herdr agent wait` does NOT wait for an agent to appear (0.8.2).** Run against a pane whose agent herdr has not detected yet, it returns `{"error":{"code":"agent_not_found"}}` **immediately** — it does not block until one shows up. R3's post-launch readiness wait therefore races the agent's own startup. Either retry the wait after a few seconds, or poll `herdr pane get <pane>` until `agent` is populated, then wait. Note the error code differs from `pane get`'s `pane_not_found`; match on the code, not on the words "not found".
- **A brand-new project directory triggers Claude Code's trust-folder dialog.** The launch `pane run` succeeds, then the agent parks at `agent_status: blocked` with `Is this a project you created or one you trust?` and **no output on `--source recent`** — read `--source visible` or `detection` to see it. Option `1. Yes, I trust this folder` is pre-highlighted, so `herdr pane send-keys <pane> Enter` clears it. Expect this on every first dispatch into a repo shepherd just created; it is a routine permission prompt under CLAUDE.md §4, not an escalation.
- `agent send` was REMOVED in 0.8.x. Its replacements split by intent: `herdr pane send-text <pane> <text>` writes literal text without Enter; `herdr agent send-keys <target> <key>...` sends key presses (`esc` is the canonical Escape name, `escape` also accepted). For prompting an agent use R4's `agent prompt`, not either of these.
- Agent names clear when the agent exits/is replaced — the ledger keys on **pane ids**, names are cosmetic labels.
- **The CLI still has no subscribe verb**, so blocking waits (R5) remain shepherd's only CLI-level signal and the Stop-hook status file remains the compensating ground truth. But the **socket** gained real push in 0.8.x: `{"method":"events.subscribe","params":{"subscriptions":[{"type":"pane.agent_status_changed"}]}}` over `~/.config/herdr/herdr.sock` (newline-delimited JSON) streams state transitions as they happen. Shepherd does not use this today; an external long-lived consumer should.
- Never run a mutating command bare to "see its help" (`herdr workspace create` executes with defaults) — command-group help only (`herdr pane`, etc.).

- **idle_prompt during background subagents:** workers driving background subagents emit `idle_prompt` notifications at every turn boundary while a subagent runs, then self-resume — several transient wakes in one task. On such a wake: read `agent_status` first; `working` = no-op (rotate the consumed file, re-arm). Only classify blocked from an actual question in the pane tail.
- **Driving an AskUserQuestion round is not worth more than one attempt.** `Tab` did nothing; `Right` advanced but then **overshot onto the review screen and stuck there** with a question still unanswered, and `Left` would not go back. Escape from that screen lands on a `Ready to submit your answers?` confirm, so **Escape twice** is what actually cancels a round — the first press is not enough. Budget one read per question, then cancel and answer in prose. Better still, tell the worker in your reply to **ask in prose from then on**; a round you cannot navigate costs several wakes and you may never see one of the questions. When you miss one, say so and ask for it restated — never guess the question and rule on your guess.
- **A worker's AskUserQuestion round renders as an interactive dialog:** multi-question rounds show one question at a time with a `☐ ☐ ☐ ✔ Submit` header. Read the others with `herdr pane send-keys <pane> Tab` between R6 reads; do NOT try to drive the selection with `pane run` (its trailing Enter confirms whatever is highlighted). `herdr pane send-keys <pane> Escape` cancels the whole round — the worker logs "User declined to answer questions", drops to `idle`, and accepts a normal single-line R4 reply carrying your rulings. That is the reliable path (see the two-Escape note above).
- **A worker that ends its turn with `SHEPHERD: blocked` reports `idle`, not `blocked`:** the herdr stall watcher will run to its full timeout and miss it. Expected — the status-file watcher is the primary signal for checkpoint pauses; the stall watcher only catches prompts that pause a worker *mid*-turn.
