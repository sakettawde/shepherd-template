**Historical only.** Kept for diffing surfaces against the current pin; never read
these recipes for syntax. Machine-specific paths were replaced by the
`<instance-root>` and `<code-dir>` placeholders when the framework became a
plugin — the recipe *shape* is the record here, not one machine's paths.

jget() { python3 -c "import sys,json,functools; d=json.load(sys.stdin); print(functools.reduce(lambda a,k: a[int(k)] if isinstance(a,list) else a[k], sys.argv[1].split('.'), d))" "$1"; }

## R2 — spawn a worker pane (sibling split, background)

```bash
herdr pane layout --pane "$HERDR_PANE_ID"    # wide → split right; narrow/tall → down
out=$(herdr pane split --current --direction right --no-focus)
pid=$(printf '%s' "$out" | jget result.pane.pane_id)
herdr pane rename "$pid" "w-<slug>"
```

If the JSON shape differs, print `$out` and read the pane id from it. Record `$pid` in the task card immediately.

## R3 — launch a worker Claude in the pane

```bash
herdr pane run "$pid" "cd <code-dir>/<project> && SHEPHERD_TASK_ID=T-NNNN SHEPHERD_STATUS_FILE=<instance-root>/ledger/status/T-NNNN.jsonl CLAUDE_CODE_SUBAGENT_MODEL=opus claude --model opus --effort <high|xhigh> --permission-mode auto"
herdr wait agent-status "$pid" --status idle --timeout 45000
```

- Tier standard → `--model opus --effort high`; heavy → `--model opus --effort xhigh` (Saket, 2026-08-19 — supersedes the 2026-08-04 fable/high standard). **Fable only on the operator's specific request, and then only `--model fable --effort high`.** Never `fable --effort max`. Verified against `claude --help` on 2026-08-19: `--model` takes the aliases `fable`, `opus`, `sonnet` or a full id; `--effort` takes low, medium, high, xhigh, max.
- `CLAUDE_CODE_SUBAGENT_MODEL=opus` pins every subagent a worker spawns (SDD implementers, Explore, Plan) to Opus — it outranks per-call overrides and agent frontmatter (Saket, 2026-07-28: no implementation subagent below Sonnet, ideally Opus). Subagent *effort* has no env control; it inherits the worker's effort, which is fine (xhigh/max ≥ the medium floor the operator wanted).
- If `--permission-mode auto` errors at launch (M0 unknown): relaunch without the flag, note it in the card Log, and raise with the operator before dispatching more work.
- `pane run` submits text + Enter atomically. Keep every line sent through it single-line, no double quotes.

## R5 — watch for completion (arm BOTH as BACKGROUND Bash tasks; either's exit wakes you)

**Heartbeat timeout is a BACKSTOP, not the signal** (Saket, 2026-08-07): the watchers fire event-driven within seconds of a Stop-hook write or a permission prompt; the timeout only catches crashed workers, hook write failures, and herdr misclassification. Set `HB` per task tier: **1800 (30m) for S/M, 3600 (60m) for L/heavy** — and the herdr wait gets `HB * 1000` ms.

Primary — **ground-truth watcher**: fires ~2s after the worker's Stop hook writes a terminal claim. Immune to herdr's focus/seen semantics.

```bash
timeout $HB sh -c 'until grep -q "\"claim\": \"\(done\|blocked\|failed\)\"\|\"event\": \"notification\"" "$1" 2>/dev/null; do sleep 2; done' _ <instance-root>/ledger/status/T-NNNN.jsonl
```

Exit 0 = terminal claim written OR a Notification-hook event (permission/idle prompt — worker stuck mid-turn); exit 124 = heartbeat with nothing new. Either way: run the monitor skill.

**Where notification events land is inconsistent** — on T-0019/T-0015 they appeared only in sibling `T-NNNN.blockN.jsonl` files, but on T-0022 (2026-07-29) a notification landed in the main `T-NNNN.jsonl`. (The `blockN`/`notifN` siblings are shepherd's own rotations of consumed files, not a hook convention.) Watch the glob so either case fires; the secondary herdr `blocked` watcher remains the reliable catcher for permission prompts:

```bash
timeout $HB sh -c 'until ls <instance-root>/ledger/status/T-NNNN*.jsonl >/dev/null 2>&1 && grep -qh "\"claim\": \"\(done\|blocked\|failed\)\"\|\"event\": \"notification\"" <instance-root>/ledger/status/T-NNNN*.jsonl 2>/dev/null; do sleep 2; done'
```

Secondary — **stall watcher**: catches approval/permission prompts that pause the worker *without* ending its turn (no Stop hook → no status line).

```bash
herdr wait agent-status "$pid" --status blocked --timeout $((HB * 1000))
```

Wake rules:
- Whichever exits first, run monitor's ladder. The sibling watcher fires later — **a wake for a task already closed or already being handled is a no-op; don't re-arm it.**
- **Why we don't wait on `done`** (verified live in the M0 canary): completion in a *focused* tab reports `idle`, never `done`, so a `--status done` wait can only expire at its timeout — a built-in delay of the full heartbeat whenever the operator is watching the pane. `idle` vs `done` still both mean "completed" when *reading* state (R7).
- 0.7.4 quirk, if you ever do need a `done` wait: it exists only on top-level `herdr wait agent-status` (`herdr agent wait --status` doesn't accept it).
- herdr wait timeouts exit 1 with JSON on stderr — heartbeat path, not an error.
- On any wake where completion is unconfirmed, run R7 and treat `idle`|`done` as completed, `blocked` as needs-input, `unknown` as inspect (R6).

## R6 — read a worker's recent output (does NOT mark it seen)

```bash
herdr pane read "$pid" --source recent-unwrapped --lines 120
```

Scan for approval/question UI before believing any completed state — herdr's Claude detection is screen-scraped and a novel prompt can render as `idle` instead of `blocked`. `herdr agent explain "$pid"` debugs misclassification.

## R7 — status snapshot

```bash
herdr pane get "$pid"     # agent, agent_status, agent_session (Claude session id → claude --resume)
herdr agent list          # all live agents
herdr pane list --workspace "$HERDR_WORKSPACE_ID"
```

Backfill the card's `session:` from `agent_session` when present. The worker's full transcript path arrives via the Stop hook in the status file (`transcript_path`) — read it there, not from herdr.

**Own identity (multi-instance).** Your own pane is `$HERDR_PANE_ID`; your own session id is the `agent_session` herdr reports for it:

```bash
herdr pane get "$HERDR_PANE_ID"   # .result.pane.agent_session.value
```

Two traps here, both checked against the real binary, not assumed:

- `agent_session` is a **nested object**, not a string — the id is at `.value`, e.g. `.result.pane.agent_session.value`.
- There is no `jq` on this machine; parse with `python3`.

**`herdr pane get` does NOT exit 0 for a missing pane.** A live pane: exit 0, the pane document on stdout. A missing pane: exit 1, a `{"error":{"code":"pane_not_found",...}}` document on **stderr**, stdout empty. Verified directly against the pinned 0.7.4:

```
$ out=$(herdr pane get w6:pZZZ 2>/dev/null); echo "rc=$? stdout=[$out]"
rc=1 stdout=[]
$ herdr pane get w6:pZZZ 2>&1 >/dev/null
{"error":{"code":"pane_not_found","message":"pane w6:pZZZ not found"},"id":"cli:pane:get"}
```

Even so, never read the exit status as the signal — a herdr-unreachable failure or a malformed document can also make it non-zero, and nothing but the `pane_not_found` code itself tells that apart from "pane gone". `${CLAUDE_PLUGIN_ROOT}/lib/shepherd-common.sh`'s `pane_probe <pane>` is the sanctioned reader: it takes stdout, falling back to stderr only when stdout is empty, and classifies whichever document it finds — never the exit code. It returns **three** states, not two:

| Return | Meaning |
|---|---|
| 0 | live — pane exists and runs a Claude session; prints the session id |
| 1 | gone — `pane_not_found`, or the pane carries no usable `agent_session` |
| 2 | unresolved — no document on either stream, not JSON, any other error code, or no usable pane object; anything else, including a missing `python3` (which propagates 127 and is normalised to 2 by `shepherd_live`) |

`pane_session <pane>` is `pane_probe` under another name (same three returns) for callers that just want an id. `shepherd_live <pane> <session>` composes it with a recorded session id for the same tri-state answer: 0 only when the pane runs exactly that session. **Only a 1 ever authorises reclaiming a lock or reservation** — a 2 is reported, never treated as death (see the sweep line kinds, the manual §8).

**Peer identity (multi-instance).** A peer's pane and session are never read from herdr directly — they come from its identity lock:

```bash
shepherd-lock check <owner-id>   # HELD <owner-id> <holder> <pane> <session> <task> <acquired>
```

Fields 4 and 5 of that line are the pane and session to probe. (`ledger/shepherds/<id>.json` is only the advisory copy of the same facts — its directory is gitignored and may be empty; the lock is the authority, never the registration file.)

`shepherd_live` and `pane_probe` are shell functions in `${CLAUDE_PLUGIN_ROOT}/lib/shepherd-common.sh`, not a standalone command — that library's own header says "never executed directly". Source it, then call the function directly:

```bash
. lib/shepherd-common.sh; shepherd_live <pane> <session>; echo $?
```

## R9 — retire a worker pane after its task closes (pane hygiene, live since 2026-07-24)

Closing the pane also ends the claude session — this is the normal close-out path. **Never send `/exit` first**: `pane run` appends to any unsubmitted draft in the input box and would submit it as a prompt.

```bash
herdr pane get "$pid"     # gather guard facts
```

Guards — ALL must pass, else leave the pane open and note which guard failed in the card Log:

1. Task card is `done|failed|abandoned` AND the card's `pane:` == `$pid` (shepherd-created, this task's).
2. `label` starts with `w-` and `agent_status` is `idle`/absent — never close a `working`/`blocked` agent.
3. `agent_session` matches the card's `session:` — a different session id means a human ran their own claude in the pane; leave it alone.
4. `focused` is false — the operator is looking at a focused pane; skip and retry on a later wake.
5. Unsubmitted input-box drafts do NOT block retirement — discard silently (Saket 2026-07-24).

```bash
herdr pane close "$pid"             # then set registry `pane:` to none if it pointed here
```

Keep-the-pane variant (rare — immediate relaunch in the same pane): `herdr pane run "$pid" "/exit"` drops to shell — but ONLY after an R6 read confirms the input box is empty.

## R10 — self-recycle (context reset in place; the operator-approved 2026-08-07, canary T-0058)

Shepherd resets its own context with `/clear` while keeping the same process (and any remote-control registration) alive — the user sees one continuous stream.

Meter (run on wakes): `scripts/self-recycle.sh meter <own-session-id>` → current context tokens. Threshold: recycle at **>300k**, only between tasks/wakes — never mid-verification.

Recycle sequence (all in ONE turn, then end the turn):

1. Commit every pending ledger/registry change (durable state is the repo).
2. **Check the input box is in normal prompt mode** — R6 read of own pane. See the bash-mode trap below; skipping this is how the whole sequence fails silently.
3. Arm the detached recovery injector (survives /clear; waits for own pane idle, then prompts). **Phrase it so it is true whether or not the clear worked** — never assert freshness:
   `scripts/self-recycle.sh inject <own-pane> 30 "Run session-start recovery per the manual section 8 and report status to the operator."`
4. Queue the clear into own pane (executes when this turn ends): `herdr pane run <own-pane> "/clear"`
5. End the turn. Do NOT queue anything after /clear — queued messages likely do not survive it; that is what the injector is for.

**Bash-mode trap (T-0085 session, 2026-08-18 — this sequence failed here).** `pane run` submits into whatever mode the input box is currently in. If the operator last ran a command with the `!` prefix, the box is in **bash mode**, and `pane run "/clear"` executes `/clear` as a *shell command* — it fails with `/bin/bash: /clear: No such file or directory` and the context is never cleared. Two consequences, both bad: shepherd carries on believing it recycled, and the already-armed detached injector later fires into a session that is not fresh, asserting a false premise. Mitigations, in order: R6-read the pane before queuing (step 2); keep the injector message premise-free (step 3); and if the clear did not take, `pgrep -af "session-start recovery"` and kill the injector before doing anything else. When in doubt, ask the operator to type `/clear` himself — that always works and costs one message.

Known facts (researched 2026-08-07): /clear keeps PID + remote-control registration (phone-side sync can glitch; registration persists); a full restart mints a NEW remote session — never restart when continuity matters; Claude Code has no programmatic clear — herdr self-injection is the mechanism; background Bash watchers do NOT survive /clear — §8 recovery re-arms them from active task cards.

## Gotchas (0.7.4)

- **Re-arming after a consumed claim (T-0071, 2026-08-14; corrected T-0080, 2026-08-18):** a naive re-arm of the R5 grep fires instantly on the already-handled terminal claim still sitting in the file. **Anchor on the COUNT OF TERMINAL CLAIMS, not on line count:**

  ```bash
  C=$(grep -c '"claim": "\(done\|blocked\|failed\)"' "$F")
  timeout $HB sh -c 'until [ "$(grep -c "\"claim\": \"\(done\|blocked\|failed\)\"" "$1")" -gt "$2" ]; do sleep 2; done' _ "$F" "$C"
  ```

  **Do NOT write `|| echo 0` on that `grep -c` (shepherd-collie, 2026-08-19 — this silently killed the T-0090 watcher).** `grep -c` prints `0` **and exits 1** when there are no matches, so `C=$(grep -c ... || echo 0)` yields the two-line string `0\n0`. `[ "$n" -gt "$C" ]` then fails every iteration with `[: Illegal number: 0`, the loop spins until its timeout, and **the watcher never fires**. The failure is silent and looks exactly like a quiet worker — the completion was only caught because an unrelated stale watcher happened to wake shepherd. `grep -c` already prints `0` on no-match, so the bare form is correct; if you want a guard against a missing file, use a parameter default instead:

  ```bash
  C=$(grep -c '"claim": "\(done\|blocked\|failed\)"' "$F" 2>/dev/null); C=${C:-0}
  ```

  General rule for every watcher: **a wait that can only ever time out is worse than no wait**, because a heartbeat exit is indistinguishable from a healthy quiet task. Sanity-check a re-armed watcher by confirming its condition is false at arming time.

  The older `wc -l` anchor is unreliable and misfired twice on T-0079/T-0080: `wc -l` counts newlines, so a status file whose last line has no trailing newline reads one short. The hook writes land unterminated and gain their newline later, so the anchor is set too low and the watcher fires on a line it was meant to skip. Counting claims is immune — the count only rises when a genuine new terminal claim is appended, whatever the newline state. Trade-off: this ignores `"event": "notification"` lines, so pair it with the R5 secondary stall watcher when a mid-turn permission prompt is plausible; for a worker parked on a checkpoint awaiting the operator, ignoring notifications is exactly what you want.
- **Interactive dialogs in a worker (T-0071, 2026-08-14):** Claude Code onboarding/select dialogs (e.g. "Set up auto mode?") swallow `pane run` input — the trailing Enter confirms whatever is highlighted (sending `3` ENTERED the wizard instead of dismissing). Use `herdr pane send-keys <pane> Escape` to cancel dialogs; verify with an R6 read before sending any prompt.

- IDs are opaque; never constructed; re-read after any mutation. A moved pane gets a NEW id.
- `agent send` writes literal text WITHOUT Enter — do not use for prompting; use `pane run`.
- Agent names clear when the agent exits/is replaced — the ledger keys on **pane ids**, names are cosmetic labels.
- No CLI event push on 0.7.4 — blocking waits (R5) are the only signal; the Stop-hook status file is the compensating ground truth.
- Never run a mutating command bare to "see its help" (`herdr workspace create` executes with defaults) — command-group help only (`herdr pane`, etc.).

- **idle_prompt during background subagents (observed T-0059, 2026-08-08):** fable workers driving background subagents emit `idle_prompt` notifications at every turn boundary while a subagent runs, then self-resume — five transient wakes in one task. On such a wake: read `agent_status` first; `working` = no-op (rotate the consumed file, re-arm). Only classify blocked from an actual question in the pane tail.
- **A worker's AskUserQuestion round renders as an interactive dialog (T-0074, 2026-08-15):** multi-question rounds show one question at a time with a `☐ ☐ ☐ ✔ Submit` header. Read the others with `herdr pane send-keys <pane> Tab` between R6 reads; do NOT try to drive the selection with `pane run` (its trailing Enter confirms whatever is highlighted). `herdr pane send-keys <pane> Escape` cancels the whole round cleanly — the worker logs "User declined to answer questions", drops to `idle`, and accepts a normal single-line R4 reply carrying your rulings. That is the reliable path.
- **A worker that ends its turn with `SHEPHERD: blocked` reports `idle`, not `blocked` (T-0074, 2026-08-15):** the herdr stall watcher will run to its full timeout and miss it. Expected — the status-file watcher is the primary signal for checkpoint pauses; the stall watcher only catches prompts that pause a worker *mid*-turn.
