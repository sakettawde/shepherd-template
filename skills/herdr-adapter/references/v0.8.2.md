# herdr 0.8.2 recipes

Command blocks are exact; notes are what running each recipe needs; the failures behind them are in the plugin's `${CLAUDE_PLUGIN_ROOT}/docs/incidents/`. Helper (no jq here):

**Placeholders.** `<instance-root>` is the shepherd instance repository — your own
working directory, so `pwd` prints it. `<code-dir>` is `SHEPHERD_CODE_DIR` from
`.shepherd/instance.env`. Fill both before sending a recipe to a pane.

**Never write `${CLAUDE_PLUGIN_ROOT}` in a command here.** This file is read with
the Read tool, so the placeholder is not substituted, and the Bash tool does not
carry that variable either — it expands to the empty string and yields a wrong
absolute path with no error (measured 2026-09-10, Claude Code 2.1.267). When a
recipe needs a file from the plugin, call `shepherd-paths <relative-path>`.

```bash
jget() { python3 -c "import sys,json,functools; d=json.load(sys.stdin); print(functools.reduce(lambda a,k: a[int(k)] if isinstance(a,list) else a[k], sys.argv[1].split('.'), d))" "$1"; }
```

## R1 — env + version gate

```bash
test "${HERDR_ENV:-}" = 1 || echo "NOT-INSIDE-HERDR"
herdr --version          # pin: herdr 0.8.2
herdr status             # server running, compatible: yes
```

## R2 — spawn a worker tab (one tab per worker, background)

```bash
out=$(herdr tab create ${HERDR_WORKSPACE_ID:+--workspace "$HERDR_WORKSPACE_ID"} --cwd <project-path> --label "w-<slug>" --no-focus)
pid=$(printf '%s' "$out" | jget result.root_pane.pane_id)
herdr pane rename "$pid" "w-<slug>"
```

One call returns the tab and its root pane (`type: tab_created`, both `focused: false`; measured 2026-09-08 on w13:t2). **A tab, never a split** (the operator's ruling, 2026-09-08): five splits of one pane leave workers ~35 columns wide and truncate the ctx status line the handoff check reads, where a tab's pane is full width. `--no-focus` leaves the operator where he is — check the focused tab is unchanged after the call — and `--workspace` is passed only when the variable is set, an unguarded `--workspace ""` being nothing like omitting it (herdr then opens the tab in the focused workspace). The pane keeps the `w-<slug>` label R9 guards on, the tab the same one for a human scanning tabs. A differing shape → print `$out` and read the ids; record `$pid` in the card at once — R9 re-reads the tab from the pane, so nothing stores a tab id.

## R3 — launch a worker Claude in the pane

```bash
herdr pane run "$pid" "cd <code-dir>/<project> && SHEPHERD_TASK_ID=T-NNNN SHEPHERD_STATUS_FILE=<instance-root>/ledger/status/T-NNNN.jsonl CLAUDE_CODE_SUBAGENT_MODEL=<model> claude -n worker-T-NNNN --model <model> --effort <effort> --permission-mode auto"
ready=0                         # poll until herdr has DETECTED and REGISTERED the agent
for i in $(seq 1 60); do
  herdr pane get "$pid" 2>/dev/null | python3 -c 'import sys,json; d=json.load(sys.stdin); p=(d.get("result") or {}).get("pane") or {}; sys.exit(0 if p.get("agent") and (p.get("agent_session") or {}).get("value") else 1)' 2>/dev/null && { ready=1; break; }
  sleep 1
done
if [ "$ready" = 1 ]; then herdr agent wait "$pid" --until idle --timeout 45000
else echo "LAUNCH-FAILED $pid: no registered agent after 60 s"; fi
```

- **No `PATH` prepend.** `shepherd-status` reaches the worker as a bare command because the shepherd plugin's `bin/` is on the Bash tool's `PATH` in every session where the plugin is enabled, and it is enabled at user scope (measured 2026-09-10 on Claude Code 2.1.267; <https://code.claude.com/docs/en/plugins-reference#file-locations-reference>). A worker on a machine without the plugin has no `shepherd-status` and falls back to the `SHEPHERD:` sentinel line, which is what the fallback is for.
- `<model>`/`<effort>` come from `.shepherd/instance.env` (`SHEPHERD_TIER_S`, `SHEPHERD_TIER_STANDARD`, `SHEPHERD_TIER_HEAVY`, each `<model>/<effort>`): `S`, `standard` (M or L) or `heavy`. The same alias goes into `CLAUDE_CODE_SUBAGENT_MODEL`, a default outranked by a per-call `model` and agent frontmatter since Claude Code v2.1.251, so subagents follow the worker; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` stays unset, subagent effort inherits, and the Sonnet floor holds because implementation stays in the worker's session ([Subagents](https://code.claude.com/docs/en/sub-agents), read 2026-09-06; incident 2026-09-06-launch-drift).
- `-n worker-T-NNNN` is a label, not a key: a live duplicate gets a suffixed variant, so the ledger keys on pane ids. `--resume` keeps the name; a plan title replaces only an *unnamed* session's label.
- `--permission-mode auto` rejected → relaunch without it, Log it, tell the operator.
- `pane run` submits text + Enter atomically: single-line, no double quotes. `herdr agent start` cannot inject env; hence `pane run`.
- **Poll before the first wait, and before R4's kickoff.** `pane run` returns in ~2 ms with the agent still unseen, so a wait issued straight after fails `agent_not_found` in ~1 ms — all five of w12:pD–pH (2026-09-02), reproduced 2026-09-08 on an agentless pane (rc 1, 1 ms). Detection and registration are separate moments: measured twice on a fresh tab, `agent` at +0.67 s and `agent_session.value` at +1.54 s, `agent_status` still `unknown` at both, `agent wait --until idle` then rc 0. That 0.87 s gap does **not** reconcile with the registry Gotchas' 3–5 s *after detection* — a warm tab against a cold start — and no number being safe to sleep for is why this polls to a 60 s ceiling instead. `ready` carries the verdict: a `for` that runs out leaves `$?` at 0 and would fall into the wait as if nothing were wrong, and running out is a failed launch — read the pane (R6), never prompt into it. Both sides of the pipe swallow errors, so a pane that never starts does not bury that verdict under 60 tracebacks.

**Reply worker** (`kind: reply`) — three additions, `cd` into the lane:

```bash
herdr pane run "$pid" "cd <lane-path> && SHEPHERD_TASK_ID=T-NNNN SHEPHERD_STATUS_FILE=<instance-root>/ledger/status/T-NNNN.jsonl SHEPHERD_WORKER_KIND=reply CLAUDE_CODE_SUBAGENT_MODEL=<model> claude -n worker-T-NNNN --model <model> --effort <effort> --permission-mode auto --disallowedTools Edit Write NotebookEdit --settings $(shepherd-paths hooks/reply-permissions.json)"
```

- Three layers, none a boundary: the detached lane stops anything landing; these guard egress. A bare name in `--disallowedTools` removes the tool. `--settings` takes a file path; its deny list fires on any subcommand, and no level can allow past it — quoting and wrappers still can. The env var turns the guardrail hook to reply mode. Plan mode is out: it ends in an approve-the-plan prompt no pane can answer (incident 2026-08-15). Read 2026-09-07: [cli-reference](https://code.claude.com/docs/en/cli-reference), [permissions](https://code.claude.com/docs/en/permissions), [permission-modes](https://code.claude.com/docs/en/permission-modes).

## R4 — kickoff / follow-up prompt to a worker

```bash
herdr agent prompt "$pid" "You are a shepherd worker. Read <instance-root>/ledger/tasks/T-NNNN.md and execute its Brief exactly." --wait --until working --timeout 15000
```

- `agent_blocked` = rejected before any input was sent — read the pane (R6), not a transport failure. `agent_prompt_stalled` = no state change within 5000 ms.
- `--wait` does not track turns: right for a kickoff into an idle pane; a follow-up into a busy worker goes without it and R5 reports.
- `pane run` is for shell commands, `agent prompt` for agents. The Brief lives in the card, never in the pane; single-line, no double quotes.

## R5 — watch for completion (ONE background Bash task per task)

```bash
shepherd-watch arm T-NNNN          # run as a BACKGROUND Bash task; never pipe it
shepherd-watch arm T-NNNN --window 3600   # …with an explicit window in SECONDS, overriding the adaptive pick below
```

Its exit is your wake → run monitor with its **first stdout line**:

| exit | first line | meaning |
|---|---|---|
| 0 | `STATUS <what>` — e.g. `STATUS claim blocked`, `STATUS notification permission_prompt` | a wake-worthy record landed; the newest is named |
| 3 | `BLOCKED` | herdr sees the worker blocked on a prompt |
| 5 | `GONE` | no agent in the pane, confirmed by three `pane get` probes over ~15 s |
| 124 | `TIMEOUT <window>s` | the window elapsed — the heartbeat backstop |
| 4 | `ARMED-ALREADY` | a `rearm` found the watchers live; no-op |
| 2 | `ERROR <why>` | bad id, no card, non-integer `--window`, nothing armable |
| 7 | `STALL-UNAVAILABLE` (stderr, with the reason) | herdr is unusable and **this call** armed only the stall watcher, so nothing runs. Not a wake: re-arm and say one line to the operator |

- One process, two watchers: the first to fire wins and kills the other — one arming, one wake. Re-arm with `arm` after every wake; `rearm T-NNNN` (fresh session) arms only what is missing; `list` / `check` show records.
- **Primary, the status-file watcher**: fires on a wake-worthy record in `ledger/status/T-NNNN.jsonl` — a terminal claim `done|blocked|failed` (once per turn), `session_end` / `stop_failure`, or a notification of kind `permission_prompt`, `elicitation_dialog` or `agent_needs_input`; `idle_prompt` is excluded on purpose (docs/incidents/2026-08-08-idle-prompt-subagents.md). The anchor is the **count of wake-worthy records** (`wake_count`) in that one file — never the `T-NNNN*.jsonl` glob, never a line count (docs/incidents/2026-08-18-watcher-deaths.md).
- **Window**: the heartbeat is a backstop, not the signal (Saket, 2026-08-07): 1800 s S/M, 3600 s L/heavy, shared by both watchers. Adaptive: newest record wake-worthy or file empty → the ceiling; anything else → **900 s**, because a turn that claimed nothing matches no watcher.
- **The window is monotonic seconds, and herdr keeps the same clock.** 0.8.2 does **not** cap `--timeout`: no maximum on `AgentWaitParams.timeout_ms` (uint64) in `${CLAUDE_PLUGIN_ROOT}/docs/herdr-schema-0.8.2.json`, none in `herdr agent wait --help`, none in the [0.8.2 CLI reference](https://raw.githubusercontent.com/herdrdev/herdr/v0.8.2/docs/next/website/src/content/docs/cli-reference.mdx) (read 2026-09-08), which documents only that a wait without `--timeout` runs indefinitely. Measured on w13:p16, 2026-09-08: `--timeout 3600000` returned `timeout` after **3600.0 s of `/proc/uptime`** but **3519 s of `date +%s`** — herdr keeps the window exactly, on a monotonic clock, while this host's realtime ran 81 s slow across that hour (~2.3 %, the drift the registry Gotchas record jumping by *hours* when WSL2 resyncs after a host sleep). The 52–55 min returns on a 60 min arm (four panes, twice, 2026-09-02) were those two clocks disagreeing, not herdr cutting anything short, so `shepherd-watch` measures its own two windows with `set_now` off `/proc/uptime`. Not the inbox watcher's: `inbox_watch` hands its seconds to `shepherd-inbox`, still counting in realtime — ~8 min of drift on a 21600 s arm.
- `permission_request` (which tool waits) and `agent_completed` are recorded, not wakes — the first may fire per tool call, the second only for background sessions (hooks-guide, read 2026-08-23; v2.1.198+). Promote either into `wake_worthy` in `shepherd-watch` only once its counts over several dispatches prove per-dialog or per-turn firing.
- **Secondary, the stall watcher** — the script's exact line, unpiped, and the ms it passes are what is LEFT of the window, never the whole of it: the wait is re-issued until the deadline, and a re-issue asking for a full window again would overshoot that deadline by up to one window:

  ```bash
  herdr agent wait "$pid" --until blocked --timeout $((remaining * 1000))
  ```

  rc 0 → `BLOCKED`; else the stderr JSON decides, never the exit code: `timeout` → **herdr's wait ended, which is not this window elapsing** — re-issued with what is left of the deadline, and only the deadline prints `TIMEOUT`; `agent_not_found` → re-probe three times over ~15 s (a probe that finds a session re-issues the wait), `GONE` only when all three find none; anything else → `STALL-UNAVAILABLE`, the status watcher carries on (`STALL-SKIPPED` when the card has no pane yet). Exit 7 reaches you only from a stall-only `arm`, or a `rearm` whose only gap was the stall watcher while an earlier status watcher may still be live.
- **NEVER pipe a watcher command**: `… | head -3` reports `head`'s exit, so a timeout looks like exit 0; the script arms bare and reads stderr from a file — run it bare too (docs/incidents/2026-08-22-t0093-cluster.md). `herdr agent wait <target> --until <status> --timeout <ms>` is the only wait form (the 0.7.4 `herdr wait` group is gone); `--until` is repeatable; timeouts exit 1 with JSON; no `--timeout` blocks forever.
- Never wait on `done` (a focused tab reports `idle`). Reading state: `idle`|`done` completed, `blocked` needs input, `unknown` inspect (R6); R7 on any unconfirmed wake.

## R6 — read a worker's recent output (does NOT mark it seen)

```bash
herdr pane read "$pid" --source recent-unwrapped --lines 120
```

Scan for approval/question UI before believing any completed state — detection is screen-scraped; a novel prompt can render as `idle`. `herdr agent explain "$pid"` debugs it; a dialog missing from `recent` shows on `visible`.

## R7 — status snapshot

```bash
herdr pane get "$pid"     # agent, agent_status, agent_session (Claude session id → claude --resume)
herdr agent list          # all live agents
herdr pane list --workspace "$HERDR_WORKSPACE_ID"
```

Backfill the card's `session:` from `agent_session` — a **nested object**, id at `.value`; parse with python3. The transcript path comes from the Stop hook, not herdr.

**Own identity:** your pane is `$HERDR_PANE_ID`; your session id is its `agent_session`:

```bash
herdr pane get "$HERDR_PANE_ID"   # .result.pane.agent_session.value
```

**Liveness is tri-state, never the exit code** (a missing pane exits 1 with `pane_not_found` on stderr; an unreachable herdr is non-zero too). `pane_probe <pane>` (alias `pane_session`, in `${CLAUDE_PLUGIN_ROOT}/lib/shepherd-common.sh`) returns **0** live and prints the session id, **1** gone (`pane_not_found`, or no usable `agent_session`), **2** unresolved (no document, not JSON, any other error); `shepherd_live <pane> <session>` is 0 only when the pane runs that exact session. **Only a 1 authorises reclaiming a lock or reservation**; a 2 is reported. Shell functions, not commands: `. lib/shepherd-common.sh; shepherd_live <pane> <session>; echo $?`.

**Peer identity:** never from herdr — `shepherd-lock check <owner-id>` prints `HELD <owner-id> <holder> <pane> <session> <task> <acquired>` (probe fields 4 and 5); `shepherd-lock live <owner-id>` answers `live|gone|unresolved`. Where to *message* a peer is its shepherd id (`${CLAUDE_PLUGIN_ROOT}/docs/protocols.md` § Ownership and handoff).

## R9 — retire a worker tab after its task closes

Closing the pane ends the claude session — the normal close-out. **Never send `/exit` first**: `pane run` would submit an unsubmitted draft.

```bash
out=$(herdr pane get "$pid"); printf '%s\n' "$out"   # gather guard facts, and read them
tid=$(printf '%s' "$out" | jget result.pane.tab_id)
herdr tab get "$tid"                                  # its pane_count
```

Guards — ALL must pass, else leave the pane and Log which failed:

1. Task card is `done|failed|abandoned` AND its `pane:` == `$pid` (this task's, shepherd-created).
2. `label` starts with `w-` and `agent_status` is `idle`/absent — never close a `working`/`blocked` agent.
3. `agent_session` matches the card's `session:` — otherwise a human ran their own claude here; leave it.
4. `focused` is false — the operator is looking at it; retry later.
5. Unsubmitted drafts do NOT block retirement — discard silently (Saket 2026-07-24).

```bash
herdr pane close "$pid"             # then set registry `pane:` to none if it pointed here
```

**The tab goes with its last pane** — closing a tab's only pane removes the tab, no `tab close` needed (measured 2026-09-08: `tab create` w13:t3 → `pane close` its root pane → the tab is gone from `tab list`). So R2's tab retires here, and only it: a `pane_count` above 1 means someone else's pane shares the tab, and the close takes shepherd's pane alone and leaves the tab standing — Log that it did.

Keep-the-pane variant (rare): `herdr pane run "$pid" "/exit"` — ONLY after R6 confirms an empty input box.

## R10 — context rollover (context reset in place)

`/clear` in place keeps the process and its remote-control registration. The meter (`shepherd-rollover decide`; `meter <own-session-id>` as fallback), the thresholds and when to run it: the manual §8.

Sequence, all in ONE turn:

1. Commit every pending ledger/registry change.
2. One command, then **end the turn**:

   ```bash
   shepherd-rollover rollover
   ```

   No argument: the recovery line defaults to `/shepherd:wake`; `--pane` for another pane; `--sound none` under `notifications: silent`.
3. Queue nothing after it.

**The foreground call is read-only** — it reads, logs, arms the detached watchdog and exits without a keystroke, because an `Escape` from the foreground reaches Claude Code as "interrupt the running tool", which was the call carrying the script (docs/incidents/2026-08-27-rollover-self-interrupt.md). It refuses (exit 2, logged, toasted) before arming when the pane is `blocked` or has no session id (check `herdr integration status`). Every keystroke comes from the watchdog after that pid exits: it refuses only a box still in bash mode (docs/incidents/2026-08-18-bash-mode-trap.md), submits `/clear`, gates on the pane's **Claude session id changing** — never on `idle`, which a shepherd pane cannot report (docs/incidents/2026-08-25-idle-gate-death.md) — and confirms the recovery prompt from the new transcript; `agent prompt`'s return value and a clean `❯` are never evidence. Exits: `0` recovered, `2` refused before anything was sent, `3` the `/clear` never took, `4` cleared but never restarted, `5` the foreground never finished; `2`–`5` reach the operator by toast; every verdict lands in `${SHEPHERD_ROLLOVER_LOG:-~/.claude/shepherd-rollover.log}`, read at wake step 10. Never restart the process when continuity matters (a restart mints a new remote session); no hook can start an interactive turn, so self-injection is the only mechanism (hooks doc, read 2026-08-25). Background Bash watchers survive `/clear` (measured 2026-08-25): a rising shell count across rollovers is expected, not a leak.

## Gotchas (0.8.2)

One line each; the incident holds the story.

- **Shepherd controls the worker pane** and prompts it whenever it judges it should; text after `❯` or an apparent human is never a reason to hold — only the operator saying stand down is. Ghost text looks like a draft: lead with a separator, then confirm the prompt landed (`agent prompt` returns the post-submission status; `pane read` shows a bare `❯`) (Saket, 2026-08-22; docs/incidents/2026-08-22-t0093-cluster.md).
- **The re-arm anchor is the count of wake-worthy records**, computed by `shepherd-watch`: never a hand-written variant, `wc -l`, or `|| echo 0` on a `grep -c` (same incident as above).
- **Dialogs swallow `pane run` input** (Enter confirms the highlighted option): `herdr pane send-keys <pane> Escape` cancels; R6 first (docs/incidents/2026-08-14-dialogs-and-consumed-claims.md).
- **Trust-folder dialog on a new directory**: the caret defaults to `2. No, exit`. `send-keys <pane> Down`, re-read, confirm it sits on `1. Yes, I trust this folder`, then `Enter` (`shepherd-smoke select_trust_yes`); routine, no escalation (docs/incidents/2026-09-02-trust-dialog-caret.md).
- **AskUserQuestion rounds**: one R6 read per question (`Tab` moved between them on T-0074, did nothing on T-0097), then `Escape` **twice** and answer in prose via R4, telling the worker to ask in prose; a missed question is restated, never guessed. **A turn ending `SHEPHERD: blocked` reports `idle`**, not `blocked` — the status-file watcher catches checkpoint pauses, the stall watcher never will (docs/incidents/2026-08-15-askuserquestion-dialogs.md).
- **`idle_prompt` under background subagents** is transient: read `agent_status` first; `working` = re-arm, no-op (incident 2026-08-08, linked from R5).
- `agent wait` on an undetected or missing agent returns `agent_not_found` at once — not `pane get`'s `pane_not_found`; match on the code.
- IDs are opaque: never constructed, re-read after any mutation; a moved pane gets a new id, agent names clear on exit. `agent send` is gone: `herdr pane send-text` writes text without Enter, `herdr agent send-keys <target> <key>...` sends keys (`esc`); prompting is R4. Never run a mutating command bare to "see its help" (`herdr workspace create` executes) — command-group help only.
